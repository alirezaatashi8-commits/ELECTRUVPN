# ELECTRUVPN — Final Deep Audit / v20

Date: 2026-09-30

## Scope

This pass reviewed the complete release tree with emphasis on runtime correctness, API authorization, subscription lifecycle, device policy enforcement, IPv4/IPv6/domain delivery, inbound/client mutation rollback, installer/CI consistency, shell safety, frontend syntax/routing, and privacy controls.

## Release changes

- No 2FA/TOTP, Google Authenticator, Google/OAuth/OpenID login was added or enabled.
- Go toolchain baseline aligned to Go 1.27; installer pins Go 1.27.1.
- Direct Go dependencies refreshed: Gin 1.12.0, JWT v5.2.3, x/crypto 0.57.0, GORM 1.31.2, GORM SQLite driver 1.6.0.
- Subscription public group endpoint received application rate limiting.
- Subscription device registration now enforces the same access policy as subscription refresh, including explicit device IDs when supplied.
- New-device approval no longer auto-activates an already-unapproved device on a later refresh; administrator approval is required.
- Security-sensitive subscription policy database failures now fail closed.
- Subscription group delivery now honors per-client expiry/status/access policies and records device observations.
- Client create/update validates subscription address family against its actual inbound.
- Subscription primary address policy is now used by the actual public subscription endpoint.
- Inbound deletion is transactional, preventing partial client deletion when the inbound delete fails.
- Inbound cloning preserves v19 subscription policy fields while generating fresh credentials.
- Device approve/revoke responses now return the updated state.
- Subscription access User-Agent identifiers are keyed HMACs instead of unsalted SHA-256 hashes.
- Privacy/security self-tests are family-aware for IPv4/IPv6/domain endpoints and use the configured panel port rather than hard-coded 2087.
- Privacy-mode script no longer requires Nginx merely to keep the panel reachable through the same VPN path, and preserves family-specific endpoint settings.
- CI/release checks are aligned with the new Go baseline.

## Build limitation

The audit environment currently has Go 1.23.2 and no outbound DNS/network access to the Go module proxy. The release now targets Go 1.27 and refreshed dependencies, so a dependency-backed `go test ./...` and production build cannot honestly be claimed here. The installer performs `go mod tidy` and the native production build on the target Ubuntu host and fails closed if compilation fails.

The final ZIP intentionally does not contain a fabricated `go.sum`; dependency checksums must be generated by the real Go module resolver on a networked build/install host.

## Known architectural boundaries

- `MaxActiveSessions` is implemented as a recent-active-device proxy, not a raw Xray/sing-box session counter.
- Link-leak protection is a request-count threshold over the last hour; it is not geolocation or country-anomaly detection.
- Exact handset model detection requires client-reported metadata or usable client hints/User-Agent inference; tunnel traffic alone cannot reliably reveal a physical phone model.
- Subscription auto-renewal remains a billing-policy flag; it does not invent a payment or charge a user without a payment-provider confirmation.
- Subscription groups store node-group/health metadata, but actual multi-node link aggregation requires an explicit node-to-client/inbound placement model; the existing system does not falsely claim to discover remote clients automatically.
