# ELECTRUVPN Production-Grade Hardening V3

This release hardens the existing BETA1 architecture without replacing the Go control plane, Xray/sing-box managers, SQLite model layer, or `/api` contract.

## Runtime and shutdown

- All long-lived background workers share one `context.WithCancel`.
- Worker goroutines are tracked by a `sync.WaitGroup` and awaited during shutdown.
- Every worker ticker is stopped with `defer ticker.Stop()`.
- Scheduler database work is context-aware through `gorm.DB.WithContext(ctx)`.
- Xray and sing-box child processes are explicitly stopped during graceful shutdown, preventing orphaned proxy processes during systemd restarts.
- HTTP server timeouts remain bounded for slow-client protection.

## Observability

- Application logging uses Go `log/slog` with JSON output by default.
- `ELECTRU_LOG_FORMAT=text` can be used for local human-readable logs.
- `ELECTRU_LOG_LEVEL=debug|info|warn|error` controls verbosity.
- Each HTTP request receives a bounded `X-Request-ID` correlation ID.
- Access logs contain method, route template, status, duration and request ID; raw URLs are intentionally not logged so token-bearing paths are not copied into centralized logs.
- Authentication failures include the correlation ID.

## Rate limiting and fail2ban

- Global and API-specific in-process rate limits remain enabled.
- `Retry-After` now reports the actual remaining fixed-window delay instead of a hard-coded one second.
- The fail2ban filter matches the structured `slog` authentication-failure event.
- The installer enables the fail2ban jail and the daily audit validates its service/filter/jail state when fail2ban is installed.

## API contract

- OpenAPI is derived against the registered Gin routes so undocumented control-plane operations are not silently omitted.
- The current v3.5 control-plane surface is documented under `/api/pro`; no fictional `/api/v3.5` or `/api/v3.5/ultra` prefix is introduced because the deployed router does not register those paths.
- The spec documents the actual Ultra, automation, scheduler, operations, subscriptions, devices, platform, multi-node and control routes.
- `400`, `401`, `403`, `429` and `500` error response contracts are reusable OpenAPI components where applicable.
- `Retry-After` is documented on `429` responses.
- Browser session authentication and v1 bearer API-key authentication are represented separately.

## Static assets and reverse proxy

- `scripts/build-assets.sh` pins esbuild `0.25.11` and produces `app.min.js` and `style.min.css`.
- The Go static-asset middleware emits ETags and one-day cache headers and supports `304 Not Modified`.
- The Nginx helper disables access logging for assets and applies cache headers at the proxy layer.
- Long-lived immutable caching is deliberately not enabled for unhashed filenames; ETag + one-day revalidation avoids stale deployments.
- Actual `.min.*` artifacts are generated by CI/release builds. This source package does not fabricate minified artifacts when the environment cannot fetch the pinned esbuild package.

## Automated assurance

- GitHub Actions runs Go formatting, vet and tests on Go 1.27.
- The web/contract job installs the pinned frontend toolchain, builds minified assets, validates JavaScript syntax, validates OpenAPI, runs routing self-tests and checks shell syntax.
- A daily systemd timer runs `security-selftest.sh`, `privacy-regression-test.sh` and `deep-audit-v35.sh` on installed hosts.
- The timer uses `Persistent=true` so a missed execution while the host is powered off is caught after the next boot.

## Hourly log retention / memory-pressure hardening

- Runtime/application logs remain structured JSON and are sent to stderr/stdout, so they are collected by systemd-journald rather than accumulated in the Go process.
- High-volume successful HTTP access events are disabled by default (`ELECTRU_ACCESS_LOG=0`); HTTP 5xx events remain logged. Set `ELECTRU_ACCESS_LOG=1` when full request-level access logging is required.
- A dedicated `electruvpn-log-vacuum.timer` runs hourly and vacuums archived journal data.
- Default retention is `1h` with a hard journal budget of `64M` (`32M` for runtime journal data).
- The currently-open journal is never deleted during vacuum, so logging is not interrupted.
- Operators can tune `ELECTRU_LOG_RETENTION` (for example `10min`, `1h`, `1days`) and `ELECTRU_LOG_MAX_SIZE` (for example `32M`, `64M`, `128M`) in `/etc/electruvpn/electruvpn.env`.
- Xray/sing-box in-process recent-log buffers are already bounded to 500 lines; these are intentionally not treated as persistent logs and are never allowed to grow without a cap.
- Security/audit records in SQLite are intentionally **not** deleted hourly. They are security history, not runtime log cache; deleting them every hour would weaken incident investigation. Subscription access logs already have their own bounded retention logic.
